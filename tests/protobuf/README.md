`schema.proto` and `types.proto` exercise the internal compiler descriptor loader.
Those fixtures do not enable JSON/gRPC transcoding; the executable codec fixtures
are described below.

`schema_descriptor.inc` contains the `FileDescriptorSet` produced by
`grpc_tools.protoc --include_imports`. Tests compile the checked-in byte array;
Python, protoc and protobuf libraries are not test/build dependencies.

To regenerate using the existing gRPC example development environment, from the
repository root:

```bash
python -m grpc_tools.protoc -Itests/protobuf --include_imports \
  --descriptor_set_out=/tmp/schema.pb tests/protobuf/schema.proto
```

Convert those bytes to the C++ `kDescriptor` array in `schema_descriptor.inc`;
the generated comment records the protobuf version. Keep both imported files
in the descriptor set. The tests compare normalized types, packing, JSON names,
recursive/imported references and all four RPC streaming shapes against these
inputs. Hand-built malformed descriptors separately cover rejection paths.

`codec.proto` is compiled directly by the built-in source loader for JIT tests.
`codec_message.inc` is an independent reference protobuf serialization of the
boundary values listed in `test_protobuf_value.cc`; it tests exact wire bytes,
including signed minima, uint32 maximum and embedded NUL/non-UTF-8 bytes. The
maximum-tag message also exercises field-operation immediates above 32 bits.
Neither fixture requires reference tools to run. The native-program regression
creates its own temporary proto source and deletes it after compilation.

`test_protobuf_message` checks the internal C++ wire-tree codec using independent
hand-encoded fixtures: packed/unpacked repeated scalars, singular embedded-message
merging, repeated empty messages, float/double/uint64 bit preservation, malformed
nested payloads, UTF-8, fixed-width packing, slot/depth/output limits and bounded
arbitrary inputs. Runtime-length repeated scalars and embedded messages are covered by frontend,
JIT and native-program regressions. Neither path adds gRPC framing. Encoding uses unpacked repeated scalars, so semantic roundtrip rather
than byte identity is expected for packed input.


`repeated_oracle.inc` is generated by Google's protobuf 6.33.5 runtime using
`generate_repeated_oracle.py`. It covers signed int32 boundaries, Unicode with
embedded NUL, empty children, duplicate singular fields and unknown fields.
Regenerate with `python tests/protobuf/generate_repeated_oracle.py` in an optional
protobuf development environment; no reference library is needed to run tests.
The runtime tests verify exact canonical output, every truncated prefix, invalid
later elements, nested shared budgets, output bounds and repeated arena reset.

`test_grpc_proxy` also runs these reference bytes over real HTTP/2 sockets on both
epoll and io_uring: compiled raw-protobuf codec routes receive one-byte DATA
fragments, reject malformed later children, and handle another request after
cancellation on the same connection. A separate native gRPC forwarding request
checks the five-byte envelope and payload survive unchanged with grpc-status 0.
This forwarding check does not imply protobuf decoding of gRPC envelopes or
HTTP/JSON transcoding. Native codec route tests require a JIT-enabled build;
unavailable kernel backends are reported as skipped.


`enum_oracle.inc` is generated by Google's protobuf 6.33.5 runtime using
`generate_enum_oracle.py` (an optional development tool). It supplies an independent
FileDescriptorSet and packed/unpacked wire expectations for unknown enum numbers,
negative values, i32 boundaries, zero defaults and repeated empty child messages.
Source-loader tests compare these enum declarations and field metadata with the
reference descriptor, and reject indirect imports and declaration-limit overflow.
The existing epoll/io_uring network tests send these bytes in one-byte HTTP/2 DATA
fragments, verify canonical response payloads plus grpc-status trailers, reject
malformed packed values and 513-element arrays, and reuse the channel after errors
and stream cancellation. No Python/protobuf installation is required to run them.


`reserved_oracle.inc` is generated by Google's protobuf 6.33.5 descriptor runtime
using `generate_reserved_oracle.py`. It includes an imported enum schema, nested
enum reservations, message names/ranges and both forms of `to max` boundaries.
Source tests compare retained reservation metadata against this independent
FileDescriptorSet, while malformed descriptor tests check wire types, missing or
duplicate endpoints, overlap, duplicate names, invalid UTF-8 and budget limits.
The gRPC network fixture now compiles `reserved.proto`; its enum oracle payload
contains a reserved-but-unknown enum number that must survive encoding unchanged.

`public.proto` re-exports `reserved.proto`; `public_root.proto` uses the exported
message, nested enum and RPC output. `generate_public_oracle.py` builds the matching
FileDescriptorSet with Google protobuf (optional, no build dependency). Source
and descriptor metadata are compared in unit tests. The existing reserved-schema
network roundtrip uses the public facade on both I/O backends.

`strings.proto` exercises escaped imports, adjacent literals with comments, escaped
JSON names and reserved metadata (control bytes, Unicode boundaries and surrogate
pairs). `generate_strings_oracle.py` optionally invokes official protoc from
`grpcio-tools==1.78.0` with `protobuf==6.33.5` to produce `strings_oracle.inc`.
Neither package is required by builds/tests. Protoc warns about non-identifier
reserved names but retains their bytes, allowing direct metadata comparison.
The schema also drives JIT and epoll/io_uring RPC roundtrip regressions.

`file_options.proto` exercises all supported standard file generator options and
publicly imports the string/enum RPC fixture. The optional
`generate_file_options_oracle.py` uses official libprotoc 31.1 (grpcio-tools 1.78.0)
to generate the committed descriptor. Source tests compare executable schema/RPCs
and reject unknown, custom, wrongly typed and duplicate options. The source parser
also accepts the historical `php_generic_services` boolean (FileOptions field 42),
which was removed from newer protoc descriptors and is therefore covered by
inline source-parser cases. JIT, native schema-removal and both network backends
exercise option-bearing schema inputs.

`field_options.proto` and `field_options_oracle.inc` compare source-loaded fields
with official libprotoc 31.1 descriptors for ctype, jstype, lazy, unverified_lazy,
deprecated and debug_redact, mixed with packing. Regenerate with
`python tests/protobuf/generate_field_options_oracle.py` in the optional
grpcio-tools environment. Unit tests also reject wrong scalar types, enum
values, duplicate options, custom options and malformed lists. No protobuf
package is needed to build or run these tests.

### Proto3 optional descriptor metadata

The internal descriptor loader retains proto3 optional field presence and its
synthetic oneof index/name. It validates singular labels, index bounds, unique
names and exactly one optional member per synthetic oneof, independent of
serialization order. Synthetic declarations share the schema field-count
ceiling. Real oneofs and oneof options remain unsupported. This is compiler
schema metadata only: `.proto` source `optional` and executable presence-aware
codecs remain unsupported, so absent and explicitly default-valued fields are
never silently collapsed by accepting this syntax.

`optional_schema_oracle.inc` comes from official libprotoc 31.1; regenerate
with `python tests/protobuf/generate_optional_schema_oracle.py` in the optional
grpcio-tools environment. It covers optional scalar/string/bytes/bool/message
fields alongside an implicit-presence scalar. Malformed synthetic oneofs are
tested with hand-built descriptors. No new test/build dependency is required.
