# 已知大响应提前使用 bulk：1 MiB HTTP 短连接代理实验

2026-10-05。候选代码保留在独立实验分支，功能验证通过，目标场景有小幅正向信号，**性能验收尚未完成**。没有推送、创建 PR 或合并。不能将本报告解读为已经确认稳定收益或完成小响应退化验收。

## 改了什么

io_uring 完整缓冲代理在已经进入 `Buffering`、且明文响应的已知 Content-Length 大于现有 256 KiB bulk 块时，首个溢出节点直接优先借用 bulk。provided-buffer 溢出复制和后续直接接收使用同一个分配策略。之前的策略依赖已累计长度或本次片段长度：首片段较小时可能先建一个 16 KiB 普通节点，之后直读还要填满这个节点的尾部。

这能在上述分片情况下避免额外普通节点及其接收/发送推进；原本就以 bulk 开始的响应不一定改变。没有声称每个请求都减少固定次数的 syscall，也没有加入运行时计数器来证明命中比例。绝大部分后续 body 已经直接接收到链尾，此改动并不是新增加一条完全零复制通路。

保持 256 KiB 块、每连接 4 块 VA、最多 1 GiB bulk VA 和 16 MiB 空闲缓存。小响应、TLS、尚未验证头部的阶段维持原有阈值，bulk 耗尽回退到普通块。没有修改 io_uring CQE/epoll IoEvent 语义、完整响应验证、同 CQE 越界检测、异步缓冲持有、取消/关闭后的回收逻辑。

## 退化检查与主机干扰

另一用户项目在测试期间间歇运行 wasm-opt、wasm-bindgen、rustc、格式化、链接和测试。没有终止或改变它们的亲和性。每个测量窗口保存 `/proc/stat` 逐核计数和服务端进程 user/kernel ticks、minor/major faults；`cpu-observation.json` 汇总 CPU 2/3/4/5 及 SMT 兄弟核 10/11/12/13。计数可以指出竞争，不能替代调用栈归因。

- reverse 相对平稳，但仍有后台活动；confirm 最后一对 HTTP 样本的兄弟核忙碌达约 65%，此前部分窗口达 99%。
- TLS 首批受强烈干扰，表观 RPS −19.10% 不作回归结论。较平稳的 repeat：573 → 575 RPS（+0.39%）、CPU/request −0.53%、p99 217.447 → 214.282 ms（−1.46%），基本持平，仍有约 5%–24% 的兄弟核后台活动。
- 64 KiB 的三批都遇到明显干扰，第一批 c128 表观 −50.33%，repeat c1 表观 −61.32%，final c128 表观 −3.89% / p99 +56.80%。这些不能证明候选退化，也不能证明无退化。部分窗口兄弟核忙碌接近 100%。完整结果保存在 `summary.csv`，没有删除不利样本。
- 所有 **84 个性能样本** 的 warmup/正式测量网络错误均为零，所有响应预检通过；零错误不代表这些样本都适合做性能归因。
- 16 MiB 仅为空闲 bulk 缓存上限，不是进程或活动响应 RSS 上限。RSS 原始值已保存，不宣称实际 RSS 恒定或下降。

结论：本轮保留了一个通过功能验证的窄范围候选；1 MiB 高并发有小幅改善信号，但缺少足够安静、完整的正反测量与 64 KiB 退化验收，因此没有标记为性能验收通过。发布或 PR 性能声明前仍需安静机器复测。
