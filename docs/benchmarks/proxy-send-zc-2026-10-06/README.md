# SEND_ZC 实验（2026-10-06）

结论：尝试了真实 SEND_ZC，但本原型不能采用，已恢复普通 SEND。当前 localhost 场景没有实际零拷贝收益；高并发出现读错误。失败补丁保存为 experiment.patch，仅用于复现与后续设计，不是可部署实现。

## 实验实现

默认关闭，启动时显式读取 RUT_EXPERIMENTAL_SEND_ZC=1。仅明文下行普通发送且长度至少 32KiB 允许 SEND_ZC，上游/TLS/file send 不采用。使用 REPORT_USAGE 观察内核复制回退。内核不支持时回退 SEND。

实验采用保守的生命周期方案：数据 CQE 带 MORE 时暂存结果，等 NOTIF 后再交给现有完整发送 proactor；部分发送也等通知后再提交剩余部分。这样保持既有 pending_ops 和缓冲区持有关系，但同时延迟连接与正文推进。这是本原型的约束，并不是 SEND_ZC 的最佳实现。

## 验证

修正后的完整网络测试 1576 项、350659 次检查通过；新增 2 项、44 次检查覆盖延迟通知、部分发送、旧 generation、取消完成、错误通知与不支持回退。7 个真实 CLI 场景通过。格式与 diff 检查通过。首次新增测试失败及修正后的日志均保留。未跑新的 sanitizer 或完整 tidy。

## 正式负载暴露的问题

同一二进制 SEND/ZC 开关，1MiB HTTP，origin 复用开启，单 worker/shard，server CPU0、origin CPU1、clients CPU4/6；每格预热2s、测量10s，nginx固定镜像。原定 SEND/ZC/ZC/SEND 四组；第二组出现无效样本后停止，没有完成 ABBA，不能用作稳定收益验收。

| 长连接 c128 | 2253 / 60.796 | 1144 / 114.941 | 11983 | 无效，不作吞吐比较 |

正式 ZC 组 315874 次提交、315874 次通知、315874 次通知报告复制、0 次不支持回退。复制比例为100%，没有观察到实际零拷贝。真实 CLI 少量请求也全部报告复制。

高并发长连接测量有11983次读错误、预热有2188次；短连接测量有803次读错误。不能将这些样本的 RPS 当作优化收益。SEND_ZC opcode 被内核接受，与内核实际避免复制是两件事。

连接故障的具体代码位置尚未通过 trace 定位；通知等待延迟与当前请求/关闭推进之间的交互是待验证原因，不能宣称已确定根因。后续实现需要分离发送完成与页释放通知，将固定上限的缓冲区持有计数、取消与关闭回收接到现有 owner 机制。真实网卡上的零拷贝、不同阈值和独立通知管理的性能尚未测量，不能外推本 localhost 原型结果。

没有推送或合并。evidence.tar.gz 保存命令、环境、日志、原始压测结果与通知计数；provenance.json 标记源码基线、补丁和实验二进制哈希。实验二进制本地保留于 /tmp/rut-send-zc-experiment-rut，运行版本恢复普通 SEND。
