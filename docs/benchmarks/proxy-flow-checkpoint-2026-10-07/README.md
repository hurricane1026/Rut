# 关闭请求发送与动态 bulk 缓存验收

隔离原型；默认实现未替换。所有测量基于正文存储复用和上一轮完整节点向量发送，16 MiB 基础空闲缓存、1 MiB HTTP proxy、单 shard、origin 复用。SEND_ZC 关闭，正文对齐实验关闭。

## 配对复测

同一二进制 A/B/B/A，预热 5 秒；c128 测量 20 秒，c1 测量 10 秒。frontend CPU2、origin CPU3、clients CPU5/7。候选同时启用严格关闭请求发送及动态缓存。

## 改动与代价

- 对已发布、严格拥有、长度至少 32 KiB 的明文 proxy Body，只在 exact Connection: close 且不可 keep-alive 时尝试一次非阻塞 send/sendmsg；SQ 有余量且 NOP 注入结果受支持才进入。成功前缀通过原有 io_uring Send 所有权继续结算：写完用 NOP CQE，部分写入提交余量，保留 MSG_MORE 与总字节计数。工作负载长连接继续异步发送；生命周期日志包含关闭连接的预检请求。
- bulk 实际借用达到 128 个时，空闲缓存上限临时由 64 块提高到 128 块，即 16 → 32 MiB。无 bulk 借用时，每个维护 tick 最多丢弃 8 块（2 MiB）最旧空闲缓存，逐步降回 16 MiB。8 次维护可从 32 降回 16 MiB；不是硬实时 8 秒承诺。原型维护接在 io_uring timer 路径，其他后端尚未接入该实验维护策略，未用于默认部署。
- c128 短连接 minor faults/响应 32.99 → 0.29；长连接 4.27 → 0.13。该指标包括进程全部 minor faults，不等同于精确正文缺页计数。
- c128 结束 RSS 均值：短连接增加约 2.4 MiB，长连接增加约 5.6 MiB；这不是峰值。每 shard 临时缓存预算增加最多 16 MiB，不能声称始终保持 16 MiB。

## 被排除的方案

统一对短、长连接立即发送：短连接有约 4% 收益，但长连接吞吐下降约 16%、尾延迟变差，已拒绝。按请求持久性选择路径来自这个对照。

将正文起点从 20 字节偏移对齐到 64 字节没有明确收益，最终候选关闭该实验。四模式探索中长连接控制前后约 7% 漂移，不能把其小幅变化作为验收结论；最终使用更稳定的配对复测。
