# 严格本地响应直接序列化实验：拒绝保留

恢复普通 sendfile 后，尝试让配置本地响应直接在 `send_buf` 中序列化，删除 `scratch[16384]` 和 scratch → send buffer 的完整响应复制。候选只修改严格本地响应的已验证策略路径；不改变后端、sendfile、TLS、连接布局、失败策略或语言功能。最终撤回候选源码及测试，仅保留实验记录和可复现的 `candidate.patch`。既有静态大响应前缀去拷贝优化继续保留。

基线源码为 `b942014e`，运行时与 `ebe20ff4` 完全相同，复用此前冻结的该版本二进制。候选为相同基线加归档中的两文件补丁；最终构建前触碰最终头文件并重新构建所有依赖，源码、补丁、二进制 SHA-256 与编译命令均归档。Release/O2、Clang、JIT ON、IPO OFF；实验 io_uring SPLICE 选项已移除。

## 正式测量

HTTP/1.1、本地 return 4093 字节、隐式 keep-alive、真实 io_uring、单 shard/worker。固定 server CPU 2、client CPU 4/5，使用既有 BoringSSL wrk 与固定 nginx 对照。每次预热 2 秒、计时 7 秒、3 次重复；组顺序 B-C-C-B，起始 engine 在两 variant 中均衡。48 行均有效，预热和正式客户端错误均为零。以下是每坐标各 6 个 Rut 样本的中位数：

| 并发 | 吞吐：基线 → 候选 | CPU µs/请求 | p99 µs |
|---|---:|---:|---:|
| 1 | 53704 → 53838（+0.25%） | 8.271 → 8.329（+0.71%） | 24 → 22.5 |
| 128 | 195967 → 197453（+0.76%） | 3.479 → 3.442（−1.04%） | 773.5 → 758.5 |

吞吐/CPU 变化约 ±1%，不视为稳定收益。p99 不能只看合并中位数：第二方向 C2/B3 原始中位数是 2757/774 µs，而第一方向是 755/773 µs；全部尖峰均保留，没有按结果排除样本。nginx 配对归一统计见 `summary.json`。

## 追加尾延迟筛查

看到上述不确定性后追加同配置 c128、每次 30 秒的 B-C-C-B，每组一次，预热 2 秒；仍夹 nginx 作漂移参考。这是事后安全筛查，每个 variant 只有两次，不能把百分比当精确效应量。

| 组 | Rut RPS | CPU µs/请求 | p50 / p95 / p99 µs | nginx RPS / p99 µs |
|---|---:|---:|---:|---:|
| B0 | 183026 | 3.740 | 676 / 778 / 3010 | 123229 / 1390 |
| C1 | 160990 | 4.248 | 704 / 2692 / 5153 | 134185 / 1138 |
| C2 | 146230 | 4.643 | 726 / 1467 / 3362 | 97784 / 3002 |
| B3 | 187490 | 3.646 | 674 / 741 / 945 | 133493 / 1495 |

宿主及 nginx 明显漂移，但两次候选均比两次基线吞吐差、CPU 更高；按 nginx 归一也未逆转。无法证明“少一次复制”带来端到端收益，故拒绝该候选。将头部多次小写从热栈移到发送 slice 可能改变缓存行为，但这只是解释假设，未采集硬件 cache 计数。另有 16 字节、5 秒单次诊断共 8 行，候选时段 nginx c1 从约 55k/22µs 降至 28.8k/1739µs，标记为受环境波动影响，仅存档，不用于收益或回退判断。全部追加数据见 `supplement-summary.json`。

## 正确性与边界

候选通过 focused 网络测试 37 项/4542 检查，完整网络测试 1558 项/349468 检查。新增测试覆盖非均匀 4093/4096 字节响应体、GET/HEAD、keep-alive/close、部分发送续传指针、容量不足时不发布不完整响应、无效或已有输出时关闭。

冻结基线/候选各执行真实 HTTP 与 TLS 的 18 项 wire 检查，均通过：完整非均匀响应体、HEAD 无体但保留长度、顺序 keep-alive、slow read、RST 后恢复；12 次 RST 前后 FD 均为 8。converter strict profile 的显式 keep-alive 双请求 pipeline 在双方均为既有 fail-close（零响应字节），只证明共同边界，不宣称此场景已支持。已有受支持 pipeline 清单由网络测试覆盖。脚本配置调整、初始不支持的转换输入以及一次端口重叠的失败记录都保留在 validation-notes.txt，最终四次 wire 检查按相同脚本串行重跑通过。

没有 TLS 或 epoll 性能结论；真实 wire 短测不能代替其性能验证。工作在独立 worktree，原始 dirty Rut 工作区未修改。未 push、未 merge。
