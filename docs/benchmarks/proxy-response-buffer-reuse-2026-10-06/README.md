# 当前响应内复用 bulk 节点（2026-10-06）

## 状态与范围

上一轮 pipe 查询消除已独立提交到 [PR #781](https://github.com/hurricane1026/Rut/pull/781)，基于 GitHub main；19 项 CI 的最终结论均为 SUCCESS 或 SKIPPED，未合并。

本轮复用候选只在实验分支 `perf/proxy-response-buffer-reuse`，提交 `d50a551f50e52a0051956578dd7ba33c7c8cc6f7`，工作目录 `/tmp/rut-perf-next-work`。基线为 `28b05945`，包含此前尚未进入 GitHub main 的 `.bounded`、直接接收和 origin 复用实验。候选不是可直接应用到当前 main 的独立补丁，也不在 PR #781 中。

正文发送完成后，最多暂存一个仍由当前响应拥有的 bulk 节点，在下一次直接接收时重新使用。只有明文、bounded、大于 256KiB 的正文及支持直接接收的后端启用。仍有 recv 持有的尾节点不会暂存；逻辑长度归零后不暴露旧数据。每节点记录物理写入高水位，跨私有复用保留，响应完成或关闭时按高水位清零归还 SlicePool。最坏暂存一块 256KiB 节点；池的整体硬上限不变。TLS 和无直接接收能力的后端不启用私有暂存。

## 定位与被撤回实验

Linux perf_event_open 用户态 IP 采样共 4641 个样本、0 丢失：约 45.2% 在 memset。另一次合法用户栈头采样中，1025 个 memset 返回地址里 963 个来自 SlicePool::free_bulk（约 94%）。这些是用户态采样占比，不能当作总 CPU 占比。短连接高并发两轮基线 CPU 计数分别为 user/kernel 115/710 和 112/715 ticks，内核态占约 86%。没有内核调用栈数据；nginx 进程采样因权限受限未完成。

曾尝试用非临时写入清零大块缓存，保持零填充保证。ABBA 中单并发短、长连接吞吐下降约 8%，高并发没有稳定收益，已撤回。旧补丁与原始数据留在证据包。首次扩展栈采样因工具变量覆盖导致解析失败，已修复后重跑；该失败运行不用于性能或调用归因。
