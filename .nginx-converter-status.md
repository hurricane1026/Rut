# nginx converter status

## CURRENT

- Integrate the implemented source listener metadata into nginx converter
  lowering and process-level differential evidence.
- RUT syntax is `listen :<port>`; the first slice supports one cleartext IPv4
  wildcard listener and allows port 0 for ephemeral tests.
- Listener metadata is restart-required process configuration, not nginx logic
  and not hot-reloadable route state.

## NEXT

1. Investigate the upstream request policy design (#252).
2. Investigate the proxied response policy design (#253).

   after dependencies are explicit.

## BACKLOG

- Dedicated serial nginx-vs-RUT process differential harness.
- General prefix, exact, `^~`, regex, and nested location selection.
- `proxy_pass` URI replacement and trailing-slash semantics.
- Multiple servers, listen/default-server selection, and `server_name`.
- Variables, rewrite phases, internal redirects, upstream groups, TLS, static
  files, error pages, and logging compatibility.

## OPEN NGINX COMPATIBILITY ISSUES

- #254 — minimal nginx converter milestone (parser/model complete; lowering and

## KNOWN SEMANTIC RISKS

- nginx version must be pinned in differential evidence.
- normalized routing URI and original forwarded request-target are distinct.
- nginx and RUT path canonicalization and prefix boundaries differ.
- Host, Connection, hop-by-hop fields, and framing cannot be compared by a
  permissive allowlist when declaring a feature `SUPPORTED`.
- nginx is not installed on the host; Docker is available for a pinned test
  dependency, but no differential test has run yet.
