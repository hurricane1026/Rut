## KNOWN SEMANTIC RISKS

- nginx version must be pinned in differential evidence.
- The request-policy baseline is nginx 1.29.7 image digest
  `sha256:1854da86e82d5dfb49a8f3d78b099adcc7e36608b207146ed95cd47937938a40`.
- normalized routing URI and original forwarded request-target are distinct.
- nginx and RUT path canonicalization and prefix boundaries differ.
- Host, Connection, hop-by-hop fields, and framing cannot be compared by a
  permissive allowlist when declaring a feature `SUPPORTED`.
- nginx is not installed on the host; Docker provides the pinned nginx test
  dependency. One converter-generated pinned nginx-vs-RUT GET vector passes,
  but this is still a manual serial test rather than a committed harness.
- The cross-thread io_uring stall is fixed and covered by a non-skipping
  real-socket regression, but full differential execution remains serial-only.
- nginx 1.29.7 uses HTTP/1.1 and omits upstream `Connection` by default. It uses
  a fixed header skip set rather than dynamic `Connection` token normalization:
  nominated ordinary fields, `Proxy-Connection`, and `Trailer` are forwarded.
- An absolute-form client target is normalized to origin-form by nginx 1.29.7;
  the first request-policy slice may reject it but must remain PARTIAL.
- The first #253 behavior increment supports only a bounded strict HTTP/1.1
  final-response/content-length serializer. HTTP/1.0, HTTP/2, HEAD, bodies,
  Upgrade, absolute-form, interim/no-body statuses, chunking, close-delimited
  framing, and response mutations remain intentional fail-closed `PARTIAL`
  limits; broader nginx response behavior is not claimed.
- The converter currently emits those bounded policies, so header-only H1.1 GET
  success is evidence only for that request/response domain. nginx accepts
  fixed Content-Length POST bodies while the current RUT request policy rejects
  them; #254 therefore remains `PARTIAL`, not `SUPPORTED`.
