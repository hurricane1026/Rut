## KNOWN SEMANTIC RISKS

- nginx version must be pinned in differential evidence.
- The request-policy baseline is nginx 1.29.7 image digest
  `sha256:1854da86e82d5dfb49a8f3d78b099adcc7e36608b207146ed95cd47937938a40`.
- normalized routing URI and original forwarded request-target are distinct.
- With a URI in `proxy_pass`, nginx replaces the matching part of its normalized
  URI, not necessarily the raw request-target: repeated slashes and dot segments
  collapse, and `%7E` becomes `~` in the observed pinned vectors.
- A slash-terminated proxied location redirects the no-slash form (`/api` to
  `/api/`) before proxying. Current RUT routing erases that trailing-slash
  distinction; the #259 bounded slice must reject it rather than approximate it.
- A Redirect action alone cannot prove the nginx source-path condition because
  canonical routing collapses `/api` and `/api/`. Public lowering must execute
  an exact raw `req.pathOnly == "/api"` guard, and the bounded H1 serializer must
  independently revalidate the origin-form raw path before emitting bytes.
- Redirect authority must use the actual port returned after `bind`/`getsockname`
  (including declared port `0`), not a listener declaration stored in the
  hot-reloaded RouteConfig.
- nginx and RUT path canonicalization and prefix boundaries differ.
- An invalid upstream status prefix is not an immediate nginx malformed-header
  502: pinned nginx 1.29.7 falls back to HTTP/0.9/close-delimited semantics,
  while RUT currently returns `ParseStatus::Error`. #266 tracks this broader
  gap. The completed malformed differential is intentionally limited to a valid
  HTTP/1.1 status line followed by an invalid empty-name header.
- Host, Connection, hop-by-hop fields, and framing cannot be compared by a
  permissive allowlist when declaring a feature `SUPPORTED`.
- nginx is not installed on the host; Docker provides the pinned nginx test
  dependency. The `%7E` success and explicit-close gateway vectors are committed
  and serialised; broader POST and keep-alive vectors remain manual evidence.
- The cross-thread io_uring stall is fixed and covered by a non-skipping
  real-socket regression, but full differential execution remains serial-only.
- io_uring TLS proxying can terminate after zero or one 8192-byte body chunk
  while streaming a 256 KiB fixed-length response through the TLS output
  watermark. This pre-existing failure is tracked in #263; future nginx TLS
  compatibility must remain unsupported until its repeated acceptance passes.
- nginx 1.29.7 uses HTTP/1.1 and omits upstream `Connection` by default. It uses
  a fixed header skip set rather than dynamic `Connection` token normalization:
  nominated ordinary fields, `Proxy-Connection`, and `Trailer` are forwarded.
- An absolute-form client target is normalized to origin-form by nginx 1.29.7;
  the first request-policy slice may reject it but must remain PARTIAL.
- The first #253 behavior increment supports only a bounded strict HTTP/1.1
  final-response/content-length serializer plus one explicit-close, bodyless
  HEAD slice. HTTP/1.0, HTTP/2, keep-alive HEAD, Upgrade, absolute-form,
  interim/no-body statuses, chunking, close-delimited framing, and response
  mutations remain intentional fail-closed `PARTIAL` limits; broader nginx
  response behavior is not claimed.
- The converter emits both bounded policies. One fixed-CL binary POST now has
  generated-RUT differential evidence, but the one-slice size bound and broader
  framing/request/response domains keep this `PARTIAL`, not general body support.
- nginx's default request buffering is observable at backend accept time. The
  #252 body increment must buffer before upstream allocation/connect; reusing
  transparent early-connect streaming would be a semantic mismatch.
- The first buffering slice is bounded by existing connection-buffer capacity;
  larger nginx request bodies remain unsupported until RUT gains a broader
  memory/file-backed body buffering primitive.
- #253 body admission distinguishes locally buffered completion from actual
  upstream upload completion. Response-before-send-CQE ordering is admitted
  only after a positive full-send completion; partial or failed writes remain
  fail closed.
- Pinned nginx consumes one upstream `Connection` field and synthesizes the
  downstream value without dynamically removing token-nominated ordinary
  fields. The bounded RUT serializer matches those tested vectors and rejects
  duplicate Connection fields; broader hop-by-hop response semantics are open.
- A connect failure has no upstream response, so #253 cannot serialize nginx's
  local gateway page. #256 must supply a separate general failure policy; the
  converter must not embed a hidden nginx-only runtime mode.
- Request-policy materialisation and downstream connection intent are separate:
  the converter now emits response `connection: "request"`, preserving explicit
  client close while the rebuilt upstream request remains reusable H1.1.
